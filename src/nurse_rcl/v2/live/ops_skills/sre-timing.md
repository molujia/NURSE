# 先后与时钟

检查价值：能缩小不确定性即可，不要求一次决定唯一根因；先指出一个具体区分问题，再依据已返回结果选择定向工具、继续浏览、有理由重读或停止。不因目录尚未读完就反复重开已有窗口问题，不强制候选对或固定流程。

问题：两端异常先后能否区分当前解释？
前提：必须已有实际测量生成的onset ID；不能用卡片发布时间、模型点估计或故障目录时间代替。
工具：inspect_candidate、inspect_dependency 或browse_index(kind=onsets)取得起点；确有必要才measure_signal；compare_timing只接受source_onset_id和target_onset_id，区间数值由工具解析。
支持：严格先后且真实边、覆盖和时钟条件成立，只支持方向一致的症状解释，不确认因果。
反证：实际先后相反应修改或反驳该方向的解释。
未知：起点缺失、区间接触或重叠、时钟不确定、边覆盖不足均保持未知，不强排先后。
停止：数据分辨率无法区分时停止，说明需要何种进一步观测；不把调查动作顺序写成故障发生顺序。
反馈选路：先简述上一步新增或未新增什么、还需区分哪个问题，再参考 investigation_routes 自主选择。该表只给合法入口，不是价值排序；可查其他目录和非首位候选。execution_history、core_reusable、new_publication 是独立维度，不把重复或复用当新证据。允许有理由重读或停止，不强制切换或耗尽预算。prior_response_target 只提示上一真实动作及合法引用，responds_to 仍须自主选择；停止不证明数据穷尽。
