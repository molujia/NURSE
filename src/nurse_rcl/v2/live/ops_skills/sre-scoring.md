# 正式定位解释

检查价值：能缩小不确定性即可，不要求一次决定唯一根因；先指出一个具体区分问题，再依据已返回结果选择定向工具、继续浏览、有理由重读或停止。不因目录尚未读完就反复重开已有窗口问题，不强制候选对或固定流程。

断言范围：explain_priority恰好一个候选；compare_candidates恰好同序的两个候选，引用同一对的competition事实。多个候选／候选对分别组织合法claims，不合并成五目标总结；原精确排名由代码展示。
续页：插入其他检查后，仍可从investigation_routes的continuation_from_action_index找回未读页；page_history关联actions中的已尝试参数。先说明需要补足的内容，再自主续读、转查或停止；不要把同绑定重复页当新增证据。

问题：正式结果为什么更支持某候选？与竞争解释的差别和不足是什么？
前提：只读已发布正式score/rank和实际分项；not_published时不能临时计算分数或称已经有排名。
工具：inspect_candidate 看正式分区；compare_candidates并排对照两个不同准入候选；read_node读取精确类型和范围。所有候选都可查，不限Top-K。
支持：用实际分项、观测和机制解释支持来源；排名与精确数值由代码展示，分数不是根因概率。
反证：调查与首位不一致时同时保留正式排名和疑点，不重排、不为首位圆说。并列哈希规则不是证据。
未知：未发布、未测和缺观测分别说明，不把published冒称正式评分实际使用。
停止：已有足够证据解释当前判断及关键限制即可停止；报告先总结，再写真实工具过程。建议只列前提与待验证动作，不假称执行过修复或验证恢复。
流程：早期步骤只解释当时交付的事实；晚到或跨步骤证据是事后综合，不倒编为当时已知。目录导航可只说明调查目的与范围，不强行声称完成了观测。
建议：precondition_refs 需引用覆盖全部目标的 observation/predicate/hypothesis；排名和未知数量不能代替观测前提。缺前提就保留未知，不凑建议；核验不会改变冻结的正式排名。
报告：所有 claim_id 都要接入组织列表，conditional_next_steps 可放 unresolved_claim_ids，不能漏掉建议。先用中文解释证据的意义与局限，少抄原字段与分数，不给出第二份排名。
反馈选路：先简述上一步新增或未新增什么、还需区分哪个问题，再参考 investigation_routes 自主选择。该表只给合法入口，不是价值排序；可查其他目录和非首位候选。execution_history、core_reusable、new_publication 是独立维度，不把重复或复用当新证据。允许有理由重读或停止，不强制切换或耗尽预算。prior_response_target 只提示上一真实动作及合法引用，responds_to 仍须自主选择；停止不证明数据穷尽。
