# 机制与区别性检查

检查价值：能缩小不确定性即可，不要求一次决定唯一根因；先指出一个具体区分问题，再依据已返回结果选择定向工具、继续浏览、有理由重读或停止。不因目录尚未读完就反复重开已有窗口问题，不强制候选对或固定流程。

判断边界：未来只读补查只能改变调查中的机制解释支持与不确定性，不能写“排名将下降／分数提高／排名区分度增强”，也不能用末尾“不改变排名”抵消前面的矛盾承诺。
转回查询：机制核验插入分页调查后，原未读续页仍由investigation_routes标明；核对page_history与actions避免误把已读页当下一页。续页、其他检查、有理由重读或停止仍由agent选择。

问题：假设需要哪些条件？已有支持、反证和未知是否足够？
前提：机制卡必须由核心真实发布；概览状态不是完整判断，先用定向检查或read_node展开AND/OR及全部必要条件。
入口：候选／比较首屏candidate_overviews直接给已发布机制和评分来源，不必先翻完症状页。顶层accepted下的反证true、子条件false／unknown分别保留；完整树仍要实际展开。两个false不能合并解释为未测或整个服务正常。
工具：inspect_candidate 或compare_candidates 找支持和缺口；从distinguishing_checks取得合法request_key后可measure_signal；check_mechanism只用已得谓词重新检查一个已发布机制，不隐式补测。
支持：必要条件成立仍要报告true的反证项和其他未决竞争解释，不能把accepted说成因果确认。
反证：任一关键条件失败或存在有效反证时清楚说明局限，可转向另一合法机制。
未知：未测不等于false，OR中的未知也不能省略；无可执行请求时说明能力缺口。
停止：已回答当前区别性问题或没有可区分的合法检查时停止；重检查不改正式机制状态、分数或排名。
反馈选路：先简述上一步新增或未新增什么、还需区分哪个问题，再参考 investigation_routes 自主选择。该表只给合法入口，不是价值排序；可查其他目录和非首位候选。execution_history、core_reusable、new_publication 是独立维度，不把重复或复用当新证据。允许有理由重读或停止，不强制切换或耗尽预算。prior_response_target 只提示上一真实动作及合法引用，responds_to 仍须自主选择；停止不证明数据穷尽。
