# 依赖与症状位置

检查价值：能缩小不确定性即可，不要求一次决定唯一根因；先指出一个具体区分问题，再依据已返回结果选择定向工具、继续浏览、有理由重读或停止。不因目录尚未读完就反复重开已有窗口问题，不强制候选对或固定流程。

问题：异常更接近本地，还是可能与真实依赖有关？
前提：caller和callee必须是本案准入候选，由工具核对指定方向的边是否实际观测；不能因服务名或相关性臆造依赖。未观测到边也是合法检查结果，不等于证明没有依赖。
工具：inspect_dependency 按caller_service_key、callee_service_key读取边和两端信息；inspect_candidate 看端点已有证据；compare_timing 使用已测起点核对允许的传播方向。
支持：真实边与对端症状只支持继续核验，不等于依赖失败已确认。
反证：方向不匹配、对端反证或必要条件失败时说明竞争解释，不把调用方慢推成被调用方自身慢。
未知：没有callee self-time、覆盖不足或未观测到边必须明确。无边记录不证明独立，无变更记录不能声称发生发布。
停止：可用工具不能补齐关键区分信息时带限制停止。调用方向、症状传播方向和因果确认分开报告。
反馈选路：先简述上一步新增或未新增什么、还需区分哪个问题，再参考 investigation_routes 自主选择。该表只给合法入口，不是价值排序；可查其他目录和非首位候选。execution_history、core_reusable、new_publication 是独立维度，不把重复或复用当新证据。允许有理由重读或停止，不强制切换或耗尽预算。prior_response_target 只提示上一真实动作及合法引用，responds_to 仍须自主选择；停止不证明数据穷尽。
