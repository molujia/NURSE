# 透明整合与正式依据（ops-scoring/1）

问题：固定脚本为何给出这个正式顺序，它依赖哪些已实际使用的证据？

前提：只对已发布的正式评分卡解释；最终报告必须等待终态 core_result_digest。provisional 卡不是最终结果，核心失败不能由模型生成排名。

工具：仅 `read_node(card_id)` 阅读 scoring 卡及关联节点。无写分、重排、阈值修改或停止核心的工具。

判别：保留实际局部/传播分项、去重、分数和并列规则；分数不是根因概率，hash 并列顺序不是额外证据。不得由已看到的 Top-1 倒推“所有条件都支持”。

支持与反证：正式依据仅指核心实际消费的证据；补充调查可能支持或削弱解释，但不参与本次分数。晚发异常、未知条件和工具确认的反证必须单列，不为圆说排名而删改。

后续：需要解释疑点时下一轮转向对应调查技能；最终报告按正式依据、补充发现、局限与条件建议分层，排名表由确定性结果直接呈现，不输出模型替代排名。

停止：没有更多有用证据时结束调查；未做的重启、回滚、干预只能作为条件建议，不能声称已经验证。每轮一个动作，读卡同样计费。
